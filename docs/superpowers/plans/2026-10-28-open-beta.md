# Open Beta Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the vertical slice into an open beta on Google Play (spec §14, step 3). One opening and a short run,
published through Play's testing tracks, with:
- the engine's net settled;
- the strong enemy beatable;
- varied puzzles;
- the game playable on every phone shape and in Italian;
- a signed release bundle that meets Play's rules;
- the closed test that a new personal developer account must pass before the open track opens.

**Architecture:** The slice's architecture stays as decision 0002 records it:
- Stockfish's move generator through the bridge, one `ChessEngine` autoload, encounters as logic nodes, screens that only render, and one atomic JSON save.
- New code follows the same shape:
  - pure static helpers for screen fitting, notation and the HP maths;
  - the encounters keep their snapshot-before-await rule;
  - the release pipeline is Makefile targets around Godot's Gradle export and Google's `bundletool`.

**Tech Stack:**
- Godot 4.7.2 and GDScript, with GUT 9.7.1.
- The GDExtension: Stockfish `sf_19` and godot-cpp `10.0.0-stable`, built with NDK r28b.
- Godot's Android Gradle build template (AGP 8.6.1), JDK 17, Android build-tools 36.1.0, and `bundletool`.
- Python 3, standard library only, for the offline tools.

**Spec:**
- `docs/superpowers/specs/2026-10-26-chess-roguelike-design.md`: §10, §11, §12, and §14 step 3.
- `docs/decisions/0002-vertical-slice.md`, the "Consequences" section, which lists the inputs to this plan.
- `docs/research/2026-10-28-open-beta-release.md`: the Play, Godot and Stockfish facts, with sources. Every number below
  that comes from Google or Godot is taken from there.

## Global Constraints

- **Versions.**
  - Godot **4.7.2-stable**, GUT **9.7.1**, Stockfish **`sf_19`** (patched only if decision 0003 adopts the light net),
    godot-cpp **10.0.0-stable**.
  - NDK **r28b or later**. r28 and later link 16 KB-aligned by default; never build Android with r27 or earlier.
  - JDK **17**.
- **Application ids.**
  - Play: **`io.github.orasz.chessroguelike`**, named **"Chess Roguelike"**. The id is permanent once uploaded.
  - Developer builds: **`io.github.orasz.chessroguelike.dev`**, named **"Chess Roguelike Dev"**.
  - The slice's `io.github.chessroguelike.slice` is retired.
- **Play bundle rules.**
  - Android App Bundle (AAB), `targetSdk` **36**, `minSdk` **24**, `arm64-v8a` only.
  - Every `.so` LOAD segment aligned to **2\*\*14** (16 KB), and native libraries stored uncompressed.
  - **No permissions** declared.
  - `versionCode` rises on every upload. The beta starts at `versionCode` **1**, `versionName` **"0.1.0"**.
- **No network access in the app.** Links open the browser through `OS.shell_open`, which needs no permission. No
  proprietary SDKs, no analytics, no ads; Play's own Android vitals are the only crash data.
- **Privacy policy** at **`https://github.com/Orasz/chess-roguelike/blob/main/PRIVACY.md`**, linked inside the app and on
  the store listing.
- **No donation link** in the app or on the store listing during the beta.
- **Languages.**
  - English source strings through `tr()`, and an Italian catalog that translates **every** one of them.
  - The opening book's `en` and `it` texts follow the same locale.
  - Any other locale shows English everywhere.
- **Art and fonts** must be redistributable in a public GPLv3 repository:
  - allowed: CC0, CC BY 4.0, CC BY-SA 4.0, and OFL for fonts;
  - CC BY-SA 3.0 counts as incompatible, and NC or ND licences are out;
  - no Nintendo or fan-ripped Pokémon assets;
  - every asset and every piece of shipped code is listed in `CREDITS.md`.
- **Secrets.** The upload keystore, its alias and its password never enter the repository, a commit, a log line or a
  Makefile. They reach Godot only through `GODOT_ANDROID_KEYSTORE_RELEASE_PATH`, `GODOT_ANDROID_KEYSTORE_RELEASE_USER` and
  `GODOT_ANDROID_KEYSTORE_RELEASE_PASSWORD`, set in the author's own shell.
- **Screen.**
  - Portrait, with a 720×1280 base, stretch mode `canvas_items`, GL Compatibility, and nearest-neighbour filtering.
  - Stretch aspect **`expand`** for windows whose width/height ratio is ≤ **0.75**, and **`keep`** (pillarbox) above that.
  - Nothing tappable or readable may sit outside the display's safe area: Android 16 forces edge-to-edge drawing.
- **Engine.**
  - Every engine command goes through `UciEngine`.
  - One engine per process.
  - Tests use `FakeEngine` or their own `UciEngine`, and never start the `ChessEngine` autoload.
  - Offline tools may start their own engines.
- **Saves stay on the phone**, in one versioned JSON file, rewritten atomically after every change.
- **Repository language.**
  - Code, comments, tests, docs and commit messages are in English. The `it` content and the Italian catalog are the
    domain exception.
  - Commits carry no AI attribution lines, and the repo-local `user.email` stays as it is.
- **Tests.** `make test` runs the Python and GUT suites headless and exits with 0. Test files are named `test_*.gd` and
  `test_*.py`.

## Builder's calls in this plan

| Topic | Call |
|---|---|
| Net strategy | A measured spike (Task 1) compares the embedded full net with Lichess's 1.1 MB light net, which needs a patch. It applies the rule written in Task 1, and the author approves the result before Task 2 |
| Strong enemy: start | Only positions whose engine evaluation, after the opponent's first move, lies in **[+150, +400] cp** from the player's side. They are computed offline and stored with the record |
| Strong enemy: win | Win at `max(cp_start + 250, 500)` cp, or by mate. The enemy bar empties linearly from `cp_start` to that target, so it always starts full. This replaces the slice's fixed +800 |
| Damage dead zone | **5** win-chance points (it was 3), so engine noise between two searches does not charge a player who follows the hint |
| Tuning acceptance | Played by the real engine, the hint policy must win **≥ 80 %** of the strong positions at Club (1200), with a median of **≤ 10** player moves. If it does not, the gain drops by 50 cp per retry, down to a floor of 150 |
| Puzzles | Any Lichess puzzle of the opening. The player must find its **first** move, and any mate also counts. In each band, mate-in-one puzzles fill at most `floor(per_band × 0.34)` places. A band with few puzzles can therefore exceed 34 % (the Beginner pool was 47 % mate-in-one in the data): known, and accepted |
| Mistake pause | After an explained mistake, the enemy's reply waits **1.5 s**, so the arrow and the sentence are read on the position they refer to. The reply is saved **before** the pause |
| Theory feedback | Each book move shows its own `why`. Completing a line says so |
| Resume | A restored battle shows its last dialogue text again |
| Back button | It goes back one screen: the battle or the overworld goes to the menu with the run kept, and the menu quits. It never quits from a battle |
| Wide screens | Pillarbox (`keep`) above an aspect ratio of 0.75. Android 16 ignores the portrait lock on screens of 600 dp or more |
| Target audience | **18 and over** for the beta: the only setting unambiguously outside the Families program. Revisit for production |
| Signing | Play App Signing with an author-made upload key. The developer APK keeps its own id, so the two never collide on a phone |
| Feedback channel | GitHub issues, linked from the About screen, plus Play's private tester feedback. No email in the app |
| Hosting the privacy policy | `PRIVACY.md` at the repository root, linked by its github.com URL. This needs no Pages setup |

## Review Focus

1. **The app is killed during the new mistake pause.** On resume, the game must show the position after the enemy's
   reply, without searching again and without charging HP twice. This is tested in Task 5 by
   `test_kill_during_the_mistake_pause_keeps_the_reply_and_charges_once`.
2. **A tablet, a foldable, a landscape window or a notched phone.** The layout must never put the dialogue off screen,
   and nothing readable may sit under a cut-out or the gesture bar. This is tested in Task 6 by
   `test_wide_windows_are_pillarboxed`, `test_safe_margins_in_viewport_units` and `test_board_fits_a_3_by_4_window`.
3. **Back is pressed anywhere**: mid-search, with the new-run confirmation open, on the run-end screen. No progress may
   be lost, and the app may never quit from a battle. This is tested in Task 6 by the four `test_back_*` tests.
4. **A phone set to Italian, or to another language.** An Italian phone sees no English string. Any other phone sees no
   Italian. Generated chess notation follows the language. This is tested in Task 8 by
   `test_every_string_has_an_italian_translation`, `test_explanations_read_in_italian` and
   `test_other_languages_fall_back_to_english`, and by the extractor's `test_check_fails_on_a_stale_catalog`.
5. **The release build is not the debug build**: a `template_release` library, a Gradle AAB, and a Play-signed install.
   It must run the engine exactly as the debug build does. This is tested in Task 10 by `make check-aab`, which checks the
   release `.so`, alignment, permissions and version, and in Task 12 by the device checklist run on the installed bundle.

### Task 4: The strong enemy's win condition, the dead zone, and a tuning run

**Files:**
- Modify:
  - `game/run/tuning.gd`: remove `DECISIVE_CP` and `MIN_BAR_RANGE_CP`; add `DECISIVE_GAIN_CP := 250` and
    `DECISIVE_MIN_CP := 500`; set `DAMAGE_DEADZONE_WP := 5.0`.
  - `game/run/hp_model.gd`, `game/battle/strong_encounter.gd`, `game/test/unit/test_hp_model.gd`,
    `game/test/integration/test_strong_encounter.gd`.
  - `game/export_presets.cfg`: add `tools/*, spike/*` to `exclude_filter`.
  - `Makefile`: the `strong-sim` target.
- Create: `game/tools/strong_sim.gd`, `game/tools/strong_sim_summary.gd`, `game/test/unit/test_strong_sim_summary.gd`,
  and `docs/research/2026-10-28-strong-tuning.md` (it records the runs).

**Interfaces:**
- Produces, in `HpModel`:
  - `static func decisive_cp(cp_start: int) -> int`, which returns `maxi(cp_start + Tuning.DECISIVE_GAIN_CP, Tuning.DECISIVE_MIN_CP)`;
  - `static func enemy_fraction(cp: int, cp_start: int) -> float`, which returns
    `clamp((decisive_cp(cp_start) − cp) / (decisive_cp(cp_start) − cp_start), 0, 1)`;
  - `static func is_decisive(cp: int, cp_start: int) -> bool`.
- `StrongEncounter` calls `is_decisive(cp_after, _cp_start)` and emits `_bar_fraction()` after the opening evaluation.
  This replaces the literal `1.0`; under the new rule it is 1.0.
- Produces `class_name StrongSimSummary extends RefCounted`, with
  `static func summarize(results: Array) -> Dictionary`.
  - The input is an array of records like `{id, outcome, player_moves, hp_lost}`.
  - It returns `{count, won_share, median_moves_to_win, mean_hp_lost}`.
- Produces the `make strong-sim RATING=1200` target. It runs
  `$(GODOT) --headless --path game -s res://tools/strong_sim.gd -- --rating $(RATING) --out ../build/strong-sim-$(RATING).json`.
  - The script plays every strong record with a real `UciEngine` of its own, at enemy Elo `clampi(RATING, 400, 2400)`.
    Task 5 adds a mistake pause, and then makes the script set it to 0.
  - Its player plays the encounter's `hint` whenever it is a legal move. Otherwise it plays the engine's best move from a
